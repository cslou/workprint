# Saved material reads and manual text edits

Production rendering reads only the exported, versioned saved-content shapes. Script action/dialogue order is preserved; a reference without media remains visible with the approved No image treatment and a text-only sheet. Missing fields are not inferred from opaque JSON or identifiers. Viewing content, history or Library never grants approval or sends a write.

Version history and Library share the framework-free bounded page reader in `@workprint/api-client`, with feature-owned React bindings and styling. Requests are manual beyond the first page. Scope/resource/filter changes create a fresh reader synchronously and dispose the previous reader; late completions cannot repopulate the new scope. Errors preserve loaded rows and the same cursor for an explicit retry. Duplicate IDs in the retained window or first page, repeated recent cursors and pages over 100 items fail closed. Pages append until a 1,000-row or serialized-content bound is reached. A displaced window announces `Showing loaded items N–M` and exposes the approved `Back to first page` beside its existing load control, inside the scroll region. Return cancels pending work, uses the bounded initial page without a fetch and settles focus before hiding the return control. The window plus initial-page content stays within 4 MiB; recent cursor history is capped at 1,000. Library keeps at most 1,000 exact selected IDs and compact display facts, not full selected version bodies, across return; scope changes discard them. Search covers only the displayed window. Ordinary small collections keep their existing appearance. Terminal pagination keeps its control until layout settlement moves focus to the first newly added visible alternative, skipping a pinned current version or locally filtered items. If a terminal Library page has no visible additions, focus returns to the dialog's Close control. Neither path steals focus from another active control.

Workspace uses pin exact versions independently of Library's latest version. History may include newer unadopted versions as well as earlier ones; those versions stay read-only. The known N earlier caption is shown only when every displayed alternative actually predates the workspace version and the final page is loaded.

Existing-record manual saves use typed leaf mappings and the explicit command controller, not flattened display text or guessed JSON paths. The inspected single-action Script, reference description and stable Shot/Panel text targets preserve every unedited field, exact dependency, identity and order. Compound Script content remains fully readable; no unapproved entry navigation or builder is introduced. Pending/unknown text is selectable and readonly. Failures retain input/base; an explicit unknown-outcome retry replays the captured command. Conflict recovery explicitly reads latest, then changes only the local base when the same target and dependencies are demonstrably preserved. Changed structure blocks continuation. Cancel closes the observer and cannot undo a committed save. Confirmed exact-use responses update the scoped public projection without inventing selection authority, chat or a turn; reload still reads authoritative storage.

Legacy labelled display/history prerequisites remain only for consumers whose producers belong to later phases. They are not production saved-work data. Flat-field fixture saves against nonexistent native context retain exact input and receive nondisclosing 404, or 401 without admission; those fixtures do not claim successful legacy-schema persistence. The saved-work test mount composes the real Shell and client without display overrides, because ordinary sign-in/conversation entry depends on the unintegrated parallel sprint. It does not replace that entry flow or add a producer/seed route. Visual comparisons also mount the real MaterialPanel read composition in inert approved framing, without substituting workspace/version results or component CSS. Visual authority is the tracked `docs/design` HTML/CSS plus the approved saved-read substitutions. Ignored inspection proposals are never comparison inputs. Reference reads validate real-path containment and record source hashes; missing or escaping references fail rather than skip or regenerate from application output. The browser and backend exposure checks exclude these test compositions from production.
