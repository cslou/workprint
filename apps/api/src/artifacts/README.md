# Saved-work domain

`store.ts` owns reads and controlled prerequisite insertion; `writers.ts` owns command effects, and `publication.ts` shares transaction-local version/dependency publication SQL. It receives a pool and the trusted native owned-conversation collaborator; it does not import native storage, the agent or backend bootstrap. Every version's origin conversation and every current-use conversation is checked against the supplied account. A missing or foreign resource has the same public failure. Supported isolated test setup calls the same domain entry points, never a seed route.

Versions and dependency edges are immutable, with owner-composite foreign keys and distinct revisions. Conversation uses are separate from Library membership: an approved use pins its exact version, while a newer saved version can remain in Library without replacing it. Unavailable producers are not synthesized; selection revision starts at zero. Text/planning persistence is enabled. Image upload persistence is available only behind the guarded inspection capability; explicit qualified local-tool configuration supplies the real verifier; absent configuration cannot publish. User video uploads are temporarily denied regardless of configuration. Built-in catalog reuse remains unavailable. Composition registers the human save capability for existing text/planning records. Exact-use commands and agent producers remain unavailable.

`content.ts` validates closed, schema-versioned content before insertion and before public projection. Shared pure shapes in `packages/contracts/src/saved-content.ts` let consumers read supported fields without interpreting arbitrary JSON. The existing operation inventory and version DTOs are unchanged.

## Existing-record command writes

`createArtifactWriters()` returns separate immutable human and assistant capabilities. Composition supplies only the human capability to authenticated `saveVersion`; a future assistant binding receives only the draft capability. Producer/approval flags are not request fields. Both writers authorize the current conversation, base origin and exact dependencies through the trusted collaborator before entering SQL. Initial authoring/import is unsupported: artifact and expected latest base are required.

Human saves preserve existing structured fields, order, stable identities and exact dependencies while changing text only. An intended use must be the exact existing use of that artifact in the conversation. Its origin is authorized before SQL, and its identity/version are rechecked under lock. Ambiguous matching reference bindings fail closed rather than choosing an arbitrary use. Planning promotion also preserves the currently used plan's structure/dependencies, so a text save cannot approve an intervening reordered assistant draft and bypass later selection-revision rules. Assistant drafts never move uses or record human changes. Saves without intended use do not invent decisions.

A short transaction serializes the trusted owner/conversation/command/operation identity, rechecks a canonical payload hash, checks the latest artifact base and commits publication, immutable version/dependencies, optional exact approved use, immutable result and manual-change journal together. Identical retries return that original result without reapplying use effects, even after later decisions. Conflicting payload reuse is invalid. The journal retains the edited base and previous exact use version separately; reads do not consume changes. No native turn, provider call, native wait or external collaborator runs inside SQL.

## Private upload coordination

`uploads/records.ts` owns immutable request/confirmation identities and short SQL lease/reservation phases; `coordinator.ts` owns the admitted bounded request; `completion.ts` commits visibility; `cleanup.ts` performs explicit bounded cleanup. `policy.ts` validates MIME/size/kind and exact existing Shot/Panel targets. Native ownership and target-origin authorization finish outside SQL, as do all storage and inspection waits. Composition supplies private S3 mechanics, never caller ownership/producer flags.

Request grants bind original metadata, issue/expiry, exact length/type and a server-owned staging key. Identical retries retain that identity; conflicting reuse fails. Confirmation binds its operation to the stored upload/conversation, serializes attempts with a 60-second lease and returns the immutable original result after success without reapplying later decisions. Unsupported, foreign, missing, mismatched and expired uploads remain unusable. Current upload admission is JPEG/PNG images only, at most 10 MiB and 4096 × 4096 pixels after verification. The lower-level 100 MiB video transport/storage/SQL ceiling is not permission to upload video. Admission is not media qualification.

**Video upload admission is temporarily closed.** After ordinary native ownership/target-origin authorization, `policy.ts` denies video requests, including old authorization identities. Confirmation rejects stored video rows before claiming an operation, replaying a cached result or performing storage/inspection work. Atomic completion repeats the image-only check under the existing owner-first lease lock. No environment or collaborator flag can re-enable video. Signed grants already issued remain replayable until expiry; denial is not revocation, deletion or rollback. The conflicting-MP4-sample-table validation defect remains deferred and unqualified; re-enablement needs separate authorization and independent verification.

**Image verification is explicit and fail-closed.** Without media configuration, confirmation still returns `not_implemented: Media verification is not available`, publishing nothing. With the exact qualified local toolchain, bounded real inspection now composes into the built backend; real PG/S3/native image tests prove JPEG/PNG publication and exact-version private readback. Prior video decoder fixtures are isolated lower-level evidence, not current user-upload qualification. Synthetic inspection collaborators prove coordination only, not decoding. A valid inspection result can publish only its captured byte snapshot and copied poster, under unique per-attempt immutable keys distinct from replayable staging. Version/dependencies, private pointer/hash, protected references, draft intended-use link and original result commit together. Technical success never approves work or chooses a Shot video; selection revision is unchanged. Private object keys never enter public version DTOs.

Owned `media` reads first authorize the exact version and native origin, then resolve only protected immutable private pointers. The service signs source/poster GETs for60seconds outside SQL; API responses use no-store and private keys never enter version DTOs. URLs are replayable bearer capabilities until expiry; scope changes cannot revoke them. Browser video playback remains unqualified in this slice.

Owner-scoped object references are reserved before writes and survive storage uncertainty or SQL rollback. Unknown attempts use new keys. Cleanup excludes referenced/protected objects, claims a separate lease, handles at most four unprotected references in pairs outside SQL, and records failures. It never deletes reference tombstones: even successful deletion cannot revoke an issued PUT or prevent an admitted late write. No Artifact deletion endpoint or background scheduler is added. See `../storage/README.md` for service provenance, bounds and actual bearer-URL replay semantics.

## Bounds and cursors

Content is at most 256 KiB; declarations additionally bound events, names, Shots, Panels and exact dependencies. Pages default to 20, with the existing contract's 1–100 range, but their serialized UTF-8 JSON also stays within 1 MiB. A byte-limited page's cursor follows the last emitted item, never the first omitted item. The shared transport keeps its 1 MiB bound for other operations/errors; successful workspace reads alone have an explicit 64 MiB aggregate budget. Workspace retains its existing 100-use bound, enough room for every valid full-content use, dependency/use metadata and the duplicated storyboard projection; the server checks the final serialized aggregate as well. Large valid records remain available through all three read surfaces and exact-version reads.

History freezes its maximum revision. Library freezes an internal per-owner publication revision, not wall-clock visibility. Every publisher acquires the owner `publication_counters` lock before Artifact or intended-use locks, then increments the counter and inserts its version in one bounded transaction. Upload completion takes that same owner lock before upload/target/reference locks and rechecks the current lease and exact target inside that transaction; concurrent manual Save cannot invert this order. Request/claim/cleanup phases never acquire a later publication lock. The first page reads that owner row FOR SHARE: it waits for an already publishing transaction and fences later writers until the page's SQL completes. Continuations select the latest version per artifact at that publication revision, so delayed commits and clock adjustments cannot change membership. Existing immutable versions receive publication zero through additive DDL, without changing content. This metadata is unrelated to conversation selection revision or approval. Exact microsecond timestamps remain immutable ordering keys only.

Cursors are signed with a process-local random key and bind account, operation, resource/filter and page size. They are bounded and reject tampering or scope changes. Restart invalidates old cursors explicitly; the consumer must begin a new read rather than silently reusing a cursor. No application cursor secret or private database field is added to a browser contract.

Database transaction mechanics live in `db/transaction.ts`: 3-second statements, 1-second idle-in-transaction timeout and an 8-second wall deadline which destroys the checked-out connection and rolls back its open transaction. Native/provider calls stay outside the transaction. The serving pool is supplied by composition and remains bounded there. Application-role validation includes ownership and database/application-schema CREATE privileges for every SET-reachable role, not only immediately inherited grants.
