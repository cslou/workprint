# Workprint

A chat-first filmmaking workspace: the assistant prepares the work; the creator directs, reviews and chooses.

## Status

Phase 2 delivers the approved React/React Aria shell, navigation and review/input/export components, with frontend consumers for all 19 closed `/v1` operations through `@workprint/api-client`, verified against **one built Mastra backend** backed by Postgres and real Supabase admission. Valid authenticated requests still return structured 501 responses; the UI presents truthful empty, unauthenticated and unavailable outcomes. **No completed filmmaking flows are implemented.** Missing prerequisites come only from labelled read-only test compositions; test mounts and fixtures are excluded from production builds. `GET /health` remains public. See the [Sprint 002](docs/sprints/sprint-002.md#final-review) and [Sprint 003](docs/sprints/sprint-003.md#final-review) Final Reviews.

Functional sign-in/native chat (P3-S1a–S1c), business persistence and exact-version approvals (P3-S2/S5/S7), uploads and Library reuse (P3-S3/S4), private media (P3-S3/S10), generation status/cancellation (P3-S8), and export processing (P3-S11–S13) remain unimplemented [Phase 3 work](docs/specs/implementation-spec-001.md). Actual generation/provider execution remains Phase 4. Muse is the intended model family, not a qualified integration.

**Private/local development only:** the app-owned entry now authenticates and bounds JSON intake before the pinned adapter can clone/parse a body. Unknown paths reject before intake; admitted bodies are capped at **1 MiB** with a **two-second body-read deadline**. `qualify:ingress` remains a required separate built-server check, not a client-timeout proof. The outstanding B-004 dependency advisory still prevents shared/public deployment; bounded ingress alone does not authorize deployment or native consumers.

## Module map

These are implemented module responsibilities, not claims of working business operations. Web folder paths below are relative to `apps/web/src/`.

| Module | Responsibility |
| --- | --- |
| `shell/` | Responsive navigation, session presentation, scoped workspace reads and feature composition, including Videos/Exports assembly. |
| `conversation/` | Composer, question/option and proposal review; local unavailable native-conversation controls. |
| `library/`, `uploads/` | Scoped Library reads, local picker and exact attachment controls; upload-metadata initiation and isolated confirmation consumers, not byte transfer. |
| `materials/`, `versions/` | Script/Assets/reference presentation; shared exact-version reads, history, manual edit/Save and Use controls. |
| `storyboard/`, `videos/` | Shot/Panel planning views and edits; candidates, per-Shot choice, generation-request list/detail/cancellation controls. |
| `media/`, `exports/` | Exact-version source access/expiry and shared single-clip viewer; direct Export, history/detail and unavailable download consumers, not processing. |
| `workspace/` | Pure ordered Shot/Panel projections and presentation numbering; no persistence or authority. |
| `api/`, `ui/` | Shared browser-client/public-origin composition, scoped settlement, pagination and exact Use calls; semantic tokens, React Aria controls, panels/dialogs and feedback. |
| `packages/contracts` | Browser-safe public schemas, errors and the closed application-operation inventory; no transport. |
| `packages/api-client` | Framework-free authenticated application transport, validation, deadlines/cancellation and local-only unavailable native methods. |
| `packages/player` | Framework-free single-clip controls/events over a supplied `HTMLVideoElement`; no source access, authentication, selection or export authority. |
| `apps/api` | One Mastra/Postgres backend with Supabase admission, closed routes and authenticated unavailable application boundaries; native storage setup is separate. No Agent, provider or workflow is enabled. |
| `apps/api/src/mastra/server.ts` | Shared app-owned entry: official Hono adapter, pre-Mastra registration hook, one loopback listener, workers, startup recovery and signal-driven drain/shutdown. |
| `apps/api/src/mastra/{admission,ingress,body}.ts` | Catalog/CORS/header-Auth admission and one bounded JSON reader; trusted identity and readable raw-byte handoff before native context creation. |
| `scripts/browser` | Playwright verification harness: `capture.ts` settles captures, `material-network.ts` observes exact consumable request allowances, and pair helpers record geometry/context and compare reference/application images with `compare.ts`. |

Backend ownership reads are declared by `application/`, implemented by `agent/mastra/` through native storage, and supplied by backend `mastra/` composition. Application code imports neither native integration subtree. No ownership route or implemented application operation is added.

Dependency direction: the shell composes features; features use shared `api/` and `ui/`, which do not import features. `api-client` depends on `contracts`; packages never import apps. Browser code/packages cannot import backend or Node modules, and only web may consume `player`. These package/server boundaries, including the framework-free player boundary, are enforced by [dependency-cruiser](.dependency-cruiser.cjs).

## Development

Prerequisites: a working Docker engine, Git/tar for the clean-export smoke, and pnpm **11.28.8** (Corepack can select the version in `package.json`). pnpm downloads the repository-local Node **24.22.1** runtime; no global Node upgrade is needed. Dependency versions are pinned in the [root](package.json), [API](apps/api/package.json) and [web](apps/web/package.json) manifests and [lockfile](pnpm-lock.yaml).

From the repository root:

```sh
pnpm install --frozen-lockfile
pnpm db:local
```

Keep that terminal open. No prior `pnpm build` is needed: `db:local` reuses the test fixture's dependency-ordered compilation of contracts, api-client and API helpers before starting storage. The development-only helper creates a uniquely labelled, ephemeral Docker Postgres on a loopback-only ephemeral port, creates separate setup/serving roles, runs the supported native initialization through `pnpm db:prepare`, and grants serving DML access. It writes credentials only to ignored, mode-0600 `outputs/local-database.env`; it refuses to overwrite an existing file. It does not use your Supabase stacks or private `.env`.

In a second terminal:

```sh
SUPABASE_URL=http://127.0.0.1:1 SUPABASE_PUBLISHABLE_KEY=health-only WORKPRINT_ENV_FILE=outputs/local-database.env pnpm dev
```

These health-only examples explicitly configure an unreachable loopback Auth target: health never calls Auth, while protected application calls cannot authenticate against this target. This is not a token-verification bypass or a working sign-in configuration. For actual admission, supply your separately authorized Supabase URL and publishable/anon key instead.

Open `http://127.0.0.1:5173`; the backend health endpoint is `http://127.0.0.1:4111/health`. `PORT` and `WEB_PORT` override those loopback ports. Stop the apps first, then Ctrl-C the database helper: it stops only its owned container and removes its unchanged environment file. **Fixture data is temporary and is lost on stop.** If the file was edited, the helper preserves it and reports that fact. After an uncatchable host/process kill, inspect the exact `workprint-fixture-<UUID>` container and its matching `workprint.fixture` label before stopping that container; never reset another stack or prune Docker resources broadly.

To build and serve the built apps while that database helper remains open:

```sh
pnpm build
SUPABASE_URL=http://127.0.0.1:1 SUPABASE_PUBLISHABLE_KEY=health-only WORKPRINT_ENV_FILE=outputs/local-database.env pnpm start
```

`pnpm build` compiles backend/shared packages with `tsc` and builds the browser with Vite; it needs no database or private environment file and no longer uses the Mastra CLI. `pnpm start` runs `apps/api/dist/src/mastra/server.js` plus Vite preview (a local verification server, not deployment configuration). `pnpm dev` initially compiles the same entry, then uses TypeScript's built-in watch and Node's `--watch` reload alongside Vite. Mastra Studio/`mastra dev` are intentionally unavailable locally. Browser output is `apps/web/dist/`; backend and separate setup code compile into `apps/api/dist/`. Test helpers compile only into ignored `.test-build/` and are not production compiler inputs or assets.

### Serving lifecycle

The single `Mastra` instance from `createBackend` is served by `@mastra/hono` **1.7.21**, with direct `hono` **4.13.14** and `@hono/node-server` **1.19.17** dependencies for app construction and the one loopback listener. Core/server remain **1.79.0**, pg **1.32.0**. The adapter adds `fetch-to-node` **2.1.0** for its supported custom-route bridge; no replacement transport is authored. OpenAPI stays unset/off. Public health remains `200 { success: true }`. Before native context registration, `ingress.ts` applies narrow CORS/preflight, public health admission, exact catalog default-deny, one online header-Auth verification and bounded JSON intake, in that order. Unknown paths/methods return JSON 404; invalid Auth returns 401 and Auth-service failure returns 503 before any intake. Catalog matching and narrow CORS parsing/decoration are shared with the native compatibility fallback through `admission.ts`. The pinned Node adapter hides GET payloads from WebRequest bodies and skips their cleanup, so ingress checks only transport framing headers (never reads before Auth): body-bearing `GET /health` returns exact 400 `invalid_input` as invalid public-health input; a catalog GET with framing authenticates first, then returns the same 400. Both declared and chunked unfinished GETs are server-closed; ordinary bodyless health stays public 200. Wrong-type/malformed/oversized/over-deadline bodies return exact 400 `invalid_input`, including declared lengths over 1 MiB; exactly 1 MiB is accepted. `body.ts` owns the single 1 MiB/two-second policy used both by intake and application routes. A new raw `Request` carries buffered bytes and the original URL/method/headers/signal through native cloning. A public response-close listener observes disconnect before awaiting Auth, without triggering the adapter's lazy body/signal getter. A transport closed during Auth never dispatches after verification; admitted requests carry combined original/transport cancellation. The temporary listener is removed when middleware settles. The trusted account is held separately from Mastra's replaced RequestContext and copied into it without a second Auth call. Rejections cancel/release the reader, finish the JSON response, then destroy the owned incoming request and close its socket. The two-second timer ends before downstream work; the inherited 180-second general server timeout remains unchanged after native context/programmatic middleware. The terminal JSON 404 and the old middleware's compatibility fallback remain; the supported serving path takes its additive trusted-identity branch.

Startup awaits native `startWorkers()` (legacy `startEventEngine()` fallback). Storage initialization respects `disableInit`; serving still cannot prepare schemas. Workflow recovery runs unless configured `off`; durable-agent recovery runs only for `auto`. Both start concurrently; failures are logged without taking down serving. SIGINT/SIGTERM closes admission, sweeps idle connections every **100 ms**, drains HTTP for **5 s**, then force-closes remaining connections. Native shutdown receives that drain bound and has another **10 s** ceiling before exit 0 (up to roughly **15 s** total). A duplicate signal inside **250 ms** is ignored; a later duplicate exits 1. These are inherited bounds, not workflow recovery/capacity qualification.

Deliberate differences from the generated entry: no browser-stream endpoints or WebSocket injection (the previously reachable `/api/agents/:agentId/browser/session` now returns JSON 404); no Studio refresh streams; no usage telemetry startup/synchronization; no private scorer-trace workflow registration. No scorers are configured; trace scoring must revisit that registration before enablement. These omissions do not enable inference. Bounded intake is a separate app-owned guard, not an upstream adapter patch.

### Privately configured development storage

The isolated fixture is sufficient for this foundation. For separately authorized, dedicated development storage, copy `.env.example` to ignored `.env` and privately supply the exact target and **different restricted serving / setup credentials**. Then run `pnpm db:prepare` before `pnpm dev`. The process rejects privileged serving connections. Reapply narrowly scoped serving grants after supported native upgrades; the local fixture does this automatically.

`db:prepare` calls **`PostgresStore.init()`**, never application-authored native DDL. There are no application-owned tables or migrations yet. When an owning feature introduces them, use the Supabase CLI migration workflow under `supabase/`, excluding native schemas; do not add a custom SQL migration runner. Shared/production targets still require separate authorization.

### Native conversation ownership foundation

`application` receives a read-only `checkOwnedConversation(verifiedAccountId, conversationId)` collaborator. Its native adapter calls `PostgresStore.getStore('memory').getThreadById({ threadId, resourceId })`, then compares `thread.resourceId` exactly with the verified account ID. Foreign and absent threads both return `not_found`; malformed IDs never reach a query, and storage failures return typed `unavailable`. All 19 application operations remain Auth-first and unavailable.

**Conversation creation rule for Sprint 004:** use the verified Supabase `accountId` unchanged as the native thread's `resourceId` (and the resource identity of its messages). Never use a caller's owner field, conversation ID, email, display name, prefix or normalized substitute. This is native storage identity, not a second conversation table. Before writing the adapter, isolated Postgres on core 1.79.0 / pg 1.32.0 returned the redacted native shape `{ id: string, resourceId: string, title: string, metadata: {}, createdAt: Date, updatedAt: Date }`; the supplied resource identity round-tripped exactly.

`apps/api/test/native-conversations.ts` creates native threads and optional messages only for isolated tests through supported storage APIs. Tests own their Postgres and teardown. The helper is not a production compiler input, bundle, asset or route; no seed endpoint is enabled.

Auth qualification requires privately supplied dedicated Supabase Auth configuration, two existing authorized synthetic identities, and restricted serving credentials identifying the approved target. Provisioning/accounts remain outside the product and serving process. Do not substitute a trusted-identity bypass or use an arbitrary shared project. R2, media tooling and real model keys are not prerequisites here.

## Configuration and safety

- `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` are required backend configuration. Supply a publishable or legacy anon key; no service-role/admin credential is needed. HTTPS is required except on loopback, and URLs cannot contain credentials, paths, query strings or fragments. The single integration calls `GET /auth/v1/user` with the bearer token and API key, uses only the verified user `id`, and has a 2-second deadline including response body. Missing/malformed/invalid/expired tokens receive HTTP 401 `unauthenticated`; verifier failures receive HTTP 503 `integration_failure`. Caller owner claims never supply identity.
- `DATABASE_URL` is serving-only. `MIGRATION_DATABASE_URL` is setup-only; root development/start commands remove it from the native child environment.
- `DEFAULT_ASSISTANT_MODEL` is required and checked for `provider/model` identifier syntax before startup. URLs, missing values and test-provider prefixes are rejected. No model is resolved or enabled. The **development fixture only** supplies `unqualified/disabled`, an inert identifier, not a real model, provider or assistant response.
- Exact Muse IDs, credential names and real-provider compatibility are not yet qualified. No provider SDK/Agent is configured and no missing provider key is silently substituted. Provider-specific credential validation belongs with the actual integration before enabling calls; identifier syntax is not that qualification.
- Actual credentials belong only in ignored private files/environment, never browser configuration, prompts or logs. Vite receives no backend environment, does not load dotenv files, and disables automatic `VITE_*` exposure. Its filesystem allowlist contains only the web app, installed dependencies and compiled browser-safe contracts/client exports—not private research or outputs. Backend `VITE_*` settings remain rejected.
- `WORKPRINT_PUBLIC_API_ORIGIN` is the public application-API build/development setting. Supply an explicit HTTPS origin (HTTP only on loopback), with no credentials/path/query/fragment. For local connectivity use `WORKPRINT_PUBLIC_API_ORIGIN=http://127.0.0.1:4111 pnpm build` (or `pnpm dev` with the documented database/Auth configuration). Missing settings preserve credential-free health smoke and render the approved unconfigured Library message; there is no production fallback. Rebuild after changing a built frontend's API origin. Root tasks strip this value from the backend child.
- `WORKPRINT_PUBLIC_SUPABASE_URL` and `WORKPRINT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are the only additional public build/development settings. Supply both or neither. The URL follows the same origin restrictions; keys must be publishable (`sb_publishable_…`) or legacy `anon`, never secret/service-role/admin credentials. Role inspection validates configuration only, not identity. Vite rejects invalid pairs without printing values; absent settings expose no credential form. Root tasks forward exactly the three public values to Vite and remove them from the serving child. Rebuild after changes. Browser and backend must point at the same separately authorized Auth deployment; never reconfigure shared SMTP/redirects for a test.
- `WORKPRINT_BROWSER_ORIGIN` is a separate optional backend setting, e.g. `http://127.0.0.1:5173`, permitting exactly that browser origin on registered application paths/methods. Unset means cross-origin access is disabled. Only Authorization/Content-Type preflight headers and GET/POST/PATCH are allowed; native/excluded routes, extra headers and unapproved origins stay denied. No wildcard or credentialed CORS is enabled. This is not deployment or live-call authorization.
- `createConfiguredBrowserClient` composes only the explicit public origin and a supplied token-provider seam; it does not implement login, refresh or a session store. `Library` requires supplied scope and owns read settlement/cancellation; missing scope does not guess an identity. Account/conversation changes invalidate results before effect cleanup, and mutations are never lifecycle effects. Its material renderer is a supplied collaborator for later page composition, not a fake saved catalogue.
- Root commands force Mastra telemetry disabled, offline tooling and explicit dotenv handling. Interrupted or failed compilation stops the pipeline; no later build/setup stage may launch. No inference, paid work, telemetry exporter, test provider or qualification endpoint is registered in production. A separately built test composition adds a protected identity probe using the same backend admission code; no environment flag enables that probe in the production artifact. Credential presence is not call authorization.
- Expected idle Postgres disconnects are logged with a sanitized SQLSTATE, not credentials or raw error payloads. The native pool discards failed idle clients and can replace them on demand. Docker fixture cleanup is registered before acquisition, verifies the preselected name/owner and exact ID, explicitly removes never-started owned containers, and retains both acquisition and cleanup errors if ownership cannot be established.

## Account and session ownership

`apps/web/src/auth/` owns public Auth validation, one persistent official `@supabase/auth-js` **2.118.0** owner, and the approved account dialogs. The SDK alone owns credentials, persistence, PKCE exchange and refresh. Recovery callback parameters are captured only for the supported SDK exchange and immediately removed from the address bar; recovery access never feeds the API token seam. Password update ends recovery through local SDK sign-out and requires fresh sign-in. Sign-in/reset errors do not disclose account existence; uncertain delivery/mutation outcomes never claim nothing happened or automatically repeat work.

The owner stores only presentation and an intent epoch plus a noncredential, same-origin access-fence marker. Password exchange uses an ephemeral official SDK client with persistence, refresh and broadcast disabled; only the sole persistent SDK client publishes through public `setSession` after checking the current intent. Standard Web Locks serialize intent registration and explicit SDK session mutations across tabs, so a stale credential response cannot overwrite a newer publication. No application credential/session store or custom refresh loop is introduced. Sign-out/switch/expiry fence token access and re-key shell scope immediately; a failed revocation cannot restore old scope on reload. Storage-event receivers do not write another fence, avoiding cross-tab feedback. Successful same-account refresh and ordinary same-account recovery preserve drafts. Although SDK 2.118 can retain a still-valid JWT after proactive rejection, the application immediately fences confirmed terminal refresh errors; retryable outages preserve valid scope. An uncertain logout remains unconfirmed when a later credential-free SDK call is a no-op. No native record is deleted and no command/provider work is replayed. Composer Send and native conversation navigation remain unavailable in this story.

Account browser tests use only disposable accounts on the owned isolated Auth/Mailpit fixture. Standard SDK recovery consumes the delivered link, never an admin-generated replacement. The network observer redacts Auth bodies, callback codes and token-bearing query values before retaining evidence, and consumes exact predeclared operation counts. Account fixtures refuse an occupied frontend port and wait for their own server readiness, rather than accepting an unrelated listener's HTTP 200. Teardown runs every owned cleanup step even when browser context closure fails, preserving all errors. Private fixture records include process, database and network ownership for verified recovery after an aborted worker. Submitted passwords are cleared before awaiting Auth; fixture cleanup closes browser contexts before stopping services so failure snapshots cannot retain credentials. `pnpm qualify:auth-evidence` runs an intentionally failing browser control and verifies that cleanup prevents private inputs reaching failure artifacts. It also pauses only its owned Auth upstream, sends a synthetic private recovery-URI value, and checks the real proxy failure logs without returning raw logs or using an actual token. Both Kong request-log sinks are disabled; fixture upstream requests have bounded timeouts and no proxy retries. The parent passes only for exactly the expected failure plus the passing proxy control and no retained private value; source-code excerpts cannot impersonate a passing control. Traces, HAR, video and storage-state captures are disabled for Auth tests. Presentation-only visual fixtures invoke no Auth and compare all 30 frozen approved examples against independent tracked opening/dialog references, with main surfaces at 1440/390/820/821 and representative states at 1440/390; they are not functional Auth evidence.
